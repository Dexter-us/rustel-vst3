Install and open

The portable download needs no installer and does not change Windows settings. Keep the extracted folder together so the plugin can find its bundled Csound files.

  1. Download Rustel-Windows-x64-Portable.zip from a successful Windows build and extract the entire ZIP to a folder you want to keep.
  2. Keep Rustel.vst3, RustelVstWorker.exe, and CsoundRuntime in the same extracted folder. The ZIP also includes rustel.exe and licenses.
  3. Add the extracted folder to VSTHost’s plugin scan paths, rescan, then load Rustel as an instrument.
  4. Start DAW playback. Wait for the editor status to say Ready, then press Evaluate to apply the score.

Installer option: The full build artifact also includes install-windows.ps1. It installs the plugin, VST3 scan helper, and Csound for the current Windows user. Review the script before running it, and restart the DAW afterward.

Build artifacts are temporary development downloads and expire after 14 days. They are not stable releases.

Use the editor

  • Evaluate or press Ctrl + Enter to compile and apply the current score.
  • Loading an example or editing text changes the draft; it does not replace the sound until you evaluate it.
  • If an edit has an error, Rustel keeps the last accepted phrase playing.
  • By default, playback follows the DAW transport, tempo, position, and loop jumps. Turn off Follow DAW for a free-running preview when the host continues processing audio while stopped.
  • Output gain starts at −6 dB. It is not a brick-wall limiter; keep monitoring volume low while testing new scores.

The phrase length controls how many cycles Rustel prepares before repeating them. Choose a cycle count that fits your pattern: a three-part progression such as <c e g> needs a phrase length divisible by three to repeat at the same point in the progression. Scores that use hosted VST3 plugins are rendered off the audio callback and then repeat as a fixed phrase.

Strudel language basics

Strudel is a live-coding language for describing musical patterns. You write JavaScript expressions and use mini-notation inside strings to describe notes and rhythms. Rustel evaluates the score, prepares a fixed-length phrase, and repeats it in time with the DAW.

Mini-notation: notes, rests, and rhythm

Space-separated events share one cycle, so adding events divides that cycle into smaller parts. Use ~ for a rest, square brackets to group and subdivide events, and * to repeat a pattern faster.

note("c4 ~ [eb4 g4] c5*2")

Angle brackets choose one item per cycle. For example, note("<c3 eb3 g3>") moves through those pitches on successive cycles. Because this plugin repeats a prepared phrase, set the phrase length so the sequence lands where you expect at the repeat boundary.

Combine and change patterns

stack() plays patterns together. Pattern methods can change timing or sound controls; for example, .slow(2) stretches a pattern across two cycles and .gain(0.3) lowers its level.

stack(
  s("bd*4").gain(0.6),
  note("c2 ~ [eb2 g1]").s("sine").slow(2).gain(0.3)
)

Use the Examples list in the editor to load a starting point, then press Evaluate. Rustel supports a native subset of the wider Strudel ecosystem; browser-only features and external services may not work in this plugin. Patterns and random choices repeat with the prepared phrase rather than evolving indefinitely.

For more examples, see the Strudel mini-notation guide and the compatibility notes for the Rustel version used by this plugin.

VST3 instruments and effects

Rustel can host installed 64-bit VST3 plugins inside its score. Click Scan VST3 plugins in the editor to scan the standard Windows folders shown there: %LOCALAPPDATA%\Programs\Common\VST3 and %CommonProgramFiles%\VST3. To include another location, click Browse for a plugin folder, choose a folder, then scan. You can also type multiple paths in Additional VST3 folders, separated by semicolons. Custom folders are shared by Rustel instances using the same data directory and saved in RustelData/vst/folders.txt.

The scanned plugin browser shows each plugin's VST3 category. Place the caret in the score and click Insert instrument or Insert effect to add an example using the exact plugin name. Sort the directory by name, type, category, MIDI tag, or manual order; use the arrows to rearrange items in manual order. Expand a row to edit its display label or optional MIDI output usable tag. Your labels, tags, and ordering are saved in RustelData/vst/directory.tsv. The MIDI tag is your own note, not a plugin test. Choose MIDI source to generate a MIDI-routing example to a Rustel synth or a scanned VST instrument; use that action only for plugins that output MIDI.

The bundled RustelVstWorker.exe examines each plugin in a separate helper process. The editor shows the plugin or bundle currently being checked. Each plugin class has a 30-second limit; if one hangs, its helper process is stopped and scanning continues with other bundles. The full scan can run for up to two hours. The helper should run without opening a console window and belongs beside Rustel.vst3 in the portable package; it is not itself a plugin folder to scan.

Play a VST3 instrument

.vsti("Plugin Name") sends score notes—including pitch, velocity, and note length—to the named instrument:

note("c2 e2 g2").vsti("Your instrument")

Process sound through an effect

.vst("Plugin Name", { parameter: value }) adds an audio effect. The effect name and parameter keys should match a plugin in the scan list:

note("c2 e2 g2")
  .vsti("Your instrument")
  .vst("Your effect", { depth: 0.5 })

Route MIDI from a hosted VST3

Some VST3 generators and processors emit MIDI note events. Rustel captures their note-on, note-off, and velocity output during phrase rendering. By default, generated notes play through Rustel’s sine synth:

note("c4 ~ e4").vsti("MIDI generator")

Choose a different built-in Rustel sound with a target directive:

// MIDI target: rustel "supersaw"
note("c4 ~ e4").vsti("MIDI generator")

Built-in targets are sine, triangle, square, sawtooth, supersaw, pulse, sbd, white, pink, brown, crackle, bytebeat, zzfx, and one. Hosted MIDI can also target Rustel sample sounds, wavetables, and KabelSalat graphs:

// MIDI target: sample "bd"
note("c4 ~ e4").vsti("MIDI generator")
// MIDI target: wavetable "wt_x"
note("c4 ~ e4").vsti("MIDI generator")
// MIDI target: graph sine(sFreq).mul(0.2).out()
note("c4 ~ e4").vsti("MIDI generator")

Use a sound name available to Rustel for the sample or wavetable; uncached library sounds load when you evaluate. The graph line takes a KabelSalat expression, where sFreq and sGate are available; send its audible branch to .out(). These routes render MIDI pitch, velocity, and note duration into the prepared phrase off the audio callback. MIDI CC, pitch bend, aftertouch, and SysEx are not routed.

To send the notes to another hosted instrument, set its plugin name as the target:

// MIDI target: vsti "Your instrument"
note("c4 ~ e4").vsti("MIDI generator")

To send notes to an available Csound instrument—including Rustel’s bundled instruments or one you define or load in the score—first enable Allow native Csound:

// MIDI target: csound "triangle"
note("c4 ~ e4").vsti("MIDI generator")

The Csound route sends MIDI pitch as fractional MIDI-note p4, velocity as p5, and note-off as the event duration. It supports up to 1,024 generated notes per phrase. The selected phrase is rendered off-thread and repeats. Hosted routing currently carries notes and velocity only; it does not route MIDI CC, pitch bend, aftertouch, or SysEx.

Rustel hosts VST3, not VST2. Scanning runs in the helper process, but plugin rendering happens in the DAW process; a faulty third-party plugin can still crash or hang the DAW. Only use plugins you trust. Keep RustelVstWorker.exe beside the plugin bundle.

Separate MIDI routes: DAW MIDI input is described in MIDI input. Hosted VST3 MIDI output is routed through the target directive above.

VST3 scan results and presets are stored in RustelData beside the portable package, unless the process already has RUSTEL_CONFIG_DIR set. Cached scan results—including failures—are reused between launches while a plugin bundle remains unchanged. Installing or changing a plugin causes it to be scanned again. To retry unchanged bundles, delete only RustelData/vst/scan.json; this leaves saved presets in place. The portable package does not change persistent Windows settings.

MIDI input from VSTHost

Rustel’s VST3 instrument accepts MIDI note-on, note-off, and velocity from the DAW. In VSTHost, connect a MIDI-generating plugin or a VSTi that outputs MIDI to Rustel’s MIDI input. Incoming notes use the waveform and envelope of the first basic oscillator note in the active score; if the score has no basic oscillator notes, Rustel uses sine. The active Strudel score can play at the same time.

This is DAW-to-Rustel MIDI input. It is separate from the hosted VST3 MIDI output route in the VST3 section. Pitch bend, MIDI CC, and aftertouch are not mapped yet.

KabelSalat audio graphs

The Rustel engine bundled with this plugin includes a native implementation of KabelSalat graph-building functions. A graph describes how oscillators, envelopes, filters, and other signal operations connect to make or process sound. In this plugin, you write the graph in the score; there is no visual node-patching editor.

Use K(...) to build a graph, and end an audible output path with .out():

$: K(sine(sFreq).mul(0.2).out())
  .note("c3 e3 g3 b3")

Here, sine makes a tone, sFreq is the current note frequency, .mul(0.2) lowers the signal level, and .out() sends it to the graph output. Graphs can also use sources such as saw and noise, envelopes such as adsr, and processors such as filters, delay, and distortion.

A graph can also process audio from an earlier stage in a Rustel pattern:

$: s("sawtooth").note("c2 e2 g2 b2")
  .FX(K(audioin().distort(0.4).mul(0.3).out()))

Here, audioin() reads the Rustel synth signal entering that graph effect. It is not a connection to the DAW track feeding this instrument. This VST still has no live external audio input.

Native limits: Some KabelSalat features that expect external MIDI, control-change, or mouse input have no input source in the native engine. The scope helper passes audio through but does not open a visual scope. Graphs are code-based and subject to Rustel’s graph and resource limits.

See the KabelSalat graph guide for the pinned Rustel engine for graph inputs, nodes, examples, and limits. KabelSalat is an adaptation of the KabelSalat project.

Load and save scores

The plugin’s score and Csound source controls use the portable Scores folder beside the plugin bundle. Rustel creates that folder when needed. This keeps your files with the extracted portable copy instead of requiring a fixed Windows user folder.

  • Use Load and Save for Rustel score text in .strudel or .txt files.
  • Use Csound files… to load or save separate .orc and .csd source text. This separate editor does not replace the Rustel score or run when you press Evaluate.
  • A saved .orc can be referenced by a Rustel score with await loadOrc("local:voice.orc") after enabling Csound and setting the trusted orchestra folder. Csound source is code; only open files you trust.
  • Keep the folder with the plugin when moving the portable setup to another location.

DAW project state also stores the score draft, last accepted score, phrase settings, gain, transport options, and window state.

Use Csound

The Windows package includes the double-precision Csound 6.18.1 runtime and standard opcode DLLs. Csound is off by default.

  1. In the plugin, turn on Allow native Csound.
  2. Choose the Csound triangle example, or define an orchestra with loadCSound.
  3. Press Evaluate, then start or resume DAW playback.
note("c3 eb3 g3 bb3")
  .csound("triangle")
  .gain(0.4)
  .slow(2)

Use .csound("name") when the orchestra expects frequency in p4; use .csoundm("name") when it expects a fractional MIDI note number and velocity-style level.

Load a trusted orchestra file

Enter the full path to a trusted folder in Trusted .orc folder, then load a file from that folder in the score:

await loadOrc("local:voice.orc")

Only load Csound scores and orchestra files you trust. Native opcodes can access files and run processes with the same permissions as the DAW. The trusted-folder setting limits where Rustel reads the orchestra text; it cannot limit what compiled orchestra code can do.

Csound phrases are prepared off the audio callback and repeat at the chosen tempo. This plugin is an instrument: it does not accept live audio from another DAW track as an effect input.

Csound event fields

Rustel schedules a Csound instrument event for each note. The p values are Csound event fields, not standalone plugin controls.

FieldWhat Rustel sends
p1Instrument name or number selected with .csound() or .csoundm().
p2Event start time.
p3Event duration in seconds.
p4Resolved frequency for .csound(), or fractional MIDI note number for .csoundm().
p5Gain for .csound(); gain × velocity × 127 for .csoundm().
p6Named event-control map, including custom controls.

Custom controls can carry different values on different note events. This example adds a brightness control to the event map and reads it in the orchestra:

loadCSound`
instr glass
  iBrightness = strtod(keymap("brightness", strget(p6)))
  aEnvelope linseg 0, .005, 1, max(p3 - .01, .001), 0
  aBody poscil p5, p4
  aPartial poscil p5 * iBrightness, p4 * 2.01
  aOut = (aBody + aPartial) * aEnvelope * .5
  outs aOut, aOut
endin
`

register('brightness', (amount, pattern) =>
  pattern.fmap(value => ({ ...value, brightness: amount })))

note("c4 eb4 g4 bb4")
  .csound("glass")
  .brightness("0.1 0.3 0.6 0.9")
  .gain(0.5)

Here each successive note gets a different brightness value. Custom values are event-level controls, not continuous live audio input. Rustel packs their names and values into p6; it does not send them as separate p7, p8, and later fields.

Command-line app

The Windows package also includes rustel.exe, the upstream Rustel command-line application. It is a separate program; its commands and features do not automatically appear in the VST3 editor.

Open PowerShell in the extracted package folder:

.\rustel.exe --help
.\rustel.exe play song.strudel
.\rustel.exe export song.strudel -o take.wav --duration 30s

See the upstream Rustel CLI guide for its full command list.

Troubleshooting

No sound

  • Confirm the DAW is playing and the score status says Ready.
  • Press Evaluate after changing the score.
  • Check the track and plugin output level. Try the built-in synth example before enabling Csound.
  • If the score uses Csound, enable Allow native Csound and keep CsoundRuntime beside Rustel.vst3 in portable mode.

Csound score does not compile

  • Check the instrument name in .csound("name") against an instr defined in the loaded orchestra.
  • Check that the needed Csound opcodes are included with the bundled runtime.
  • Try the built-in Csound example to confirm Csound is enabled and available.

Score does not repeat as expected

Rustel prepares a bounded phrase and repeats it. Set the phrase length to a multiple of the pattern’s progression length when you need the same alignment at every repeat boundary.

Current limitations

  • This is an instrument, not a DAW audio-input effect. KabelSalat can process Rustel’s internal graph signal, but the plugin does not receive live audio from another track. VST2, MIDI output from Rustel to the DAW, external hardware, and external sample libraries are not supported.
  • Hosted VST3 MIDI routing currently supports note-on, note-off, and velocity only. MIDI CC, pitch bend, aftertouch, SysEx, and channel preservation when routing into a hosted VSTi are not supported yet.
  • The package supports Csound 6.18 or later in the 6.x series. Csound 7 and 32-bit hosts are not supported.
  • Phrases are prepared and repeated; patterns do not evolve indefinitely. Random choices repeat with the prepared phrase.
  • Seeking and loop jumps reset sounding voices; sustained notes that began before the new position are not reconstructed.
  • This development build has not completed plugin-validator or Windows DAW certification. Test scanning, editor open/close, state reload, tempo changes, seeking, and export in your host.
